# friendo v0.2.0

Chat + live map joins the original Expert console, keeping friendo's neon Ratatui presentation while making the request-to-result path easier to follow.

- **Chat is the default presentation.** A focused composer accepts ordinary text, Unicode, and multiline paste; attributed conversation cards retain exact user statements and expose command/results. Enter submits, Esc browses, and i returns to typing.
- **Expert remains available.** Press F2 to switch without replacing the run, draft, active work, or historical position, or start with `friendo --ui-mode expert run`. UI mode is independent of NORMAL/YOLO and execution admission.
- **The map and Understanding panel remain visible.** Wide terminals place them beside the conversation; narrow terminals keep a compact map above it. Understanding distinguishes recorded intent, model-reported interpretation, observed evidence, unresolved conflicts, and stale revisions. It does not invent private hidden reasoning or certainty.
- **Evidence is inspectable.** Expand tool cards, press F3 for selected-card provenance, F4 for correction through the existing Rewire operations, F5 for retained outbound context, or F6 to focus the map. Cards, topology, and Understanding use the same selected journal prefix.
- **Tool outcomes remain precise.** Session acknowledgments, observed nonzero exits, timeouts, incomplete capture, and complete exit-zero results have distinct labels. A historical action without completion evidence remains outcome unknown.
- **Input and review regressions are fixed.** Mode changes preserve drafts and focus; invalid submissions retain editable text; read-only historical/replay controls cannot interrupt the live controller or append events. Corrections keep their canonical operation and long input visible.

Existing configuration files work with the new version and default to Chat when `ui_mode` is absent. To choose Expert in a v0.2.0-only configuration, set `ui_mode = "expert"`; the CLI override also works. Keep the new field out of a configuration still shared with v0.1.0, which rejects unknown fields. Existing provider credential references continue to work; no credential value belongs in TOML.

NORMAL remains the default autonomy policy, shell evaluation remains disabled by default, and default executable admission remains `echo`, `pwd`, and `whoami`. Provider protocols, process behavior, schema-1 JSONL journals, and Protobuf are unchanged. Switching presentation does not dispatch work or change policy. The installed v0.1.0 binary is not replaced by source changes or release publication.

The Chat/Expert feature commit passed native CI on Linux and macOS with 101 Rust tests and on Windows with 99 platform-specific tests, plus the Unix terminal journeys. Local macOS/Apple Silicon preflight also passed, including formatting, Clippy, release guards, and real local HTTP/process fixtures. These fixtures do not contact a hosted provider. The separately documented live Anthropic `whoami` loop verified the installed v0.1.0 release; it is not a new v0.2.0 live-provider test. See [build status](https://github.com/rainmana/friendo/blob/v0.2.0/docs/build-status.md) for version-specific validation and limits.

Choose the archive for Linux x86-64, macOS Apple Silicon, macOS Intel, or Windows x86-64, verify its SHA-256 entry, extract it, and run `friendo doctor` or `friendo demo`. Packages include the executable, LICENSE, README, an example configuration, and exact source identity. Credentials, workspace configuration, generated runs, the QA fixture, and index state are excluded.

Linux requires glibc 2.35 or newer. macOS builds target macOS 13 and are tested on macOS 15; they are unsigned and not notarized. Windows x64 MSVC builds use a static C runtime and are tested on Windows Server 2022; they are unsigned. See [release instructions](https://github.com/rainmana/friendo/blob/v0.2.0/docs/releases.md) for checksums, targets, and source.

This remains an early, narrow version. Sessions use pipes rather than terminal emulation. Execution admission is not an OS sandbox. Arbitrary natural-language constraints and semantic disagreement are not automatically enforceable; disk resume, rollback, migration, and discovery are unavailable. No universal model compatibility, production-readiness, signing, or reproducible-build claim is made.
